# blanco

Configuration for my daily drivers, managed with [GNU Stow](https://www.gnu.org/software/stow/).

## Machines

All three run Fedora with [niri](https://github.com/YaLTeR/niri) and share `dotfiles/config` and `dotfiles/local`. Machine-specific packages live in an overlay under `dotfiles/hosts/` (`work/`, `blanco/`, `lady-grey/`) selected by hostname.

| | Personal | Work | lady-grey |
|---|---|---|---|
| Model | ASUS ROG Zephyrus G14 (2024, GA403UI) | Lenovo ThinkPad X1 Carbon Gen 13 | Microsoft Surface Pro 4 |
| CPU | AMD Ryzen 9 8945HS (8C/16T) | Intel Core Ultra 7 268V (8C/8T) | Intel Core i5-6300U (2C/4T) |
| GPU | Radeon 780M + NVIDIA RTX 4070 Mobile | Intel Arc Graphics 140V | Intel HD Graphics 520 |
| Memory | 32 GB | 32 GB | 8 GB |

lady-grey is a Home Assistant wall tablet in the loft. The system side (packages, linux-surface kernel, greetd, Docker services, `/etc/default/loft-kiosk`) is provisioned by `the-loft` (`hosts/lady-grey`); this repo owns its desktop, deployed as the kiosk user `rodnik`.

Everything on the personal laptop runs on the AMD iGPU; the RTX 4070 is optional. To enable it: install RPM Fusion, then `akmod-nvidia xorg-x11-drv-nvidia-cuda`, reboot, and run apps on the dGPU with `__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia <app>`.

## Structure

Each tool is its own stow package mirroring `$HOME`:

```
dotfiles/
  config/       # ~/.config payloads, stowed everywhere
    fastfetch fish fuzzel gtk-3.0 gtk-4.0 kitty niri noctalia nvim tmux vlc xdg-desktop-portal
  local/        # ~/.local payloads, stowed everywhere
    yazi niri-gather-workspaces
  hosts/
    work/       # overlay, stowed only on the work host
      config/   niri noctalia systemd
      local/    claude-code-work od-connect dev-connect-{devserver,www,www_fbsource_configerator}
                workplace metamate
    blanco/     # overlay, stowed only on the personal host
      config/   kitty niri noctalia systemd
      local/    chromium-newwindow dunst-mask loft music-assistant
    lady-grey/  # overlay, stowed only on the Surface kiosk
      config/   niri noctalia systemd
      local/    kiosk
scripts/        # deploy, bootstrap, setup-autologin, git-bootstrap, add-package, test, tests/
system/         # payloads for paths outside $HOME (/etc); not stowed
```

Untracked, per-machine files that configs pick up when present: `~/.config/fish/local.fish` (fish override seam), `~/.config/mimeapps.list` (rewritten by desktop apps; defaults are set by `deploy.sh`), `~/.config/niri/noctalia.kdl` (generated by noctalia on every theme change, gitignored; `config.kdl` includes it so niri's colours follow the wallpaper), and `.env` (`DEVSERVER_HOST`, sourced by the launchers).

## Usage

[`scripts/deploy.sh`](scripts/deploy.sh) stows the shared packages plus this host's overlay and sets MIME defaults. It is idempotent and non-destructive: symlinks are refreshed, and real files that would conflict are reported (`SKIP`) and never clobbered. It exits non-zero if anything was skipped. Stow runs with `--no-folding`, so each file is linked individually and files an app writes into `~/.config/<tool>` land in the real directory, not this repo.

```bash
./scripts/deploy.sh              # stow everything for this host
./scripts/deploy.sh --dry-run    # show what stow would do

stow --dir=dotfiles/config --target=$HOME --adopt fish    # pull live edits into the repo
stow --dir=dotfiles/config --target=$HOME --delete fish   # remove symlinks
```

On a fresh Fedora install, [`scripts/bootstrap.sh`](scripts/bootstrap.sh) runs first (it refuses on the work host and on lady-grey): packages, noctalia, yazi (built with `cargo`, since Fedora doesn't package it), flatpaks, tty1 autologin, `deploy.sh`, and git config.

To add a shared package, run `./scripts/add-package.sh <name>`, which moves `~/.config/<name>` into `dotfiles/config` and stows it. A machine-specific package goes in the host's overlay instead, and `deploy.sh` selects the overlay by hostname (`WORK_HOST`/`BLANCO_HOST`/`LADY_GREY_HOST`).

## Tests

[`scripts/test.sh`](scripts/test.sh) runs `scripts/tests/test_*.sh`. Each deploys into a throwaway `$HOME` and asserts on the result. CI runs it on every push and pull request. Requires `stow`.

```bash
./scripts/test.sh              # all tests
./scripts/test.sh dry_run      # tests whose filename contains "dry_run"
```

## Packages

Configs are self-explanatory; notes below cover only what isn't obvious from the files.

**fish.** `config.fish` sources `local.fish` when present. `conf.d/dev-connect-history.fish` collapses `dev connect … -y <token>` history entries that differ only in the token. `conf.d/autologin-niri.fish` is described under Autologin. The `calavera`, `fjord`, `helarctos`, `lady-grey`, `viking`, `woodstock` and `space-needle` functions ssh to the loft hosts via `__loft_ssh`: bare, they set the terminal title to the host name and attach to (or create) a `loft` tmux session; with arguments they run the command over plain ssh. The greeting shows Fastfetch with the Laiko portrait (`fastfetch/laiko.txt`, `$1`–`$6` colour markers mapped in `config.jsonc`, honoured because the logo type is `file`, not `file-raw`).

**kitty.** `ctrl+left` is bound to follow links (kitty dropped `open_url_modifiers` in 0.19). `ctrl+shift+e` runs a `hints` kitten that also matches scheme-less `www.` URLs. Its regex must stay in single quotes: kitty's `shlex_split` eats unquoted backslashes and the binding silently matches nothing. `xdg-open` rejects scheme-less arguments, so `blanco` overrides `--program` in `local.conf` (pulled in by `globinclude local.conf`; `work` has none).

**xdg-desktop-portal.** `niri-portals.conf` is the stock niri file plus `FileChooser=gtk;`. Without it Flatpak apps (ungoogled Chromium) get no file picker. `gtk` is pinned alone because the GNOME backend needs a GNOME session.

**tmux.** `Alt-c` (or `prefix + C`) runs `scripts/toggle-console.sh`, which stashes the active pane in a hidden `_stash` window and joins it back on the next press.

**vlc.** `vlcrc` tracks only the non-default keys. Saving in VLC's preferences replaces the symlink with a real file, which `deploy.sh` then reports as a `SKIP`. `deploy.sh` makes VLC the video/audio default when `vlc.desktop` exists.

**niri.** The shared `config.kdl` includes `noctalia.kdl` (optional, generated) and each host's `local.kdl`. Each overlay declares named workspaces and startup apps, the lock bind, the lid-close action, the noctalia backdrop layer rule, and `honor-xdg-activation-with-invalid-serial` (noctalia v5 needs it for notification actions). On `work`, the `work` workspace is pinned to the external Dell. `lady-grey` declares one named workspace per kiosk app and starts the kiosk (see its overlay). Both hosts bind `Ctrl+Print` for screen recording; `blanco` also binds the G14's `Fn+F6` snip key (sent as `Super+Shift+S`). Binds in `local.kdl` merge into the shared `binds`. `niri-gather-workspaces` (`Super+Ctrl+Y`) moves every non-empty workspace from the laptop panel to the external output after docking, keeping `personal` on the laptop.

**yazi.** Ships a launcher (`kitty yazi %f`, handles `inode/directory`) and a PNG icon, because fuzzel is built without webp.

### noctalia (shared + host overlays)

All hosts run noctalia v5 as a systemd user service (`systemd/noctalia.service`, `Restart=on-failure`) rather than niri `spawn-at-startup`, so a crash doesn't silently take down the bar, wallpaper and lock screen together. Stow only links the unit: enable it with `systemctl --user enable noctalia.service` (`bootstrap.sh` does for `blanco`; on `lady-grey` run it as `rodnik`).

`config.toml` (shared) is hand-written, and each host adds a `host.toml`. v5 merges every `*.toml` in `~/.config/noctalia/` over its defaults in filename order, so `host.toml` wins over `config.toml`; arrays are replaced, not appended, so `host.toml` restates the whole `bar.main.start` and `control_center.shortcuts` lists. The untracked `~/.local/state/noctalia/settings.toml` (GUI changes) layers on top. To keep a GUI change, copy the key from `noctalia config export` into `config.toml` (both hosts) or `host.toml` (this host) and delete it from `settings.toml`. Wallpaper paths stay in `settings.toml`: automation rewrites them every few minutes. Validate with `noctalia config validate`. The built-in `niri` theme template is enabled, so niri's border colours follow the wallpaper.

`work`'s `host.toml` restricts the lock screen to the external monitor (`DP-1` at the office, `DP-6` at home; it falls back to the laptop panel when neither is connected) and turns the lock screen widgets off. `blanco`'s turns them off too, holds its lock screen monitor and login-box layout, and puts `media` before `active_window` in the bar. Both hosts enable the `noctalia/screen_recorder` plugin and put its toggle in the control-center shortcuts (`work` also has a `recorder` bar widget). `blanco` records H.264/AAC MP4 (Messenger rejects Opus audio in MP4) with the Flathub `com.dec05eba.gpu_screen_recorder` (installed by `bootstrap.sh`, along with `slurp`) because Fedora's Mesa has no H.264 encoder and Messenger rejects AV1; the plugin only falls back to the flatpak when no native `gpu-screen-recorder` is on `PATH`, so don't install the dnf package. `work` records MKV in AV1 with the native binary, from a fork (`hsimah/noctalia-official-plugins`, declared as a `[[plugins.source]]` in its `host.toml` and restating the `official` and `community` sources, since arrays are replaced) that adds a `container` setting (upstream PR #135): the stock plugin writes MP4, whose `moov` atom sits at the end of the file so recordings won't play in a browser until remuxed, and work's Intel encoder exposes AV1 but not H.264. Sources added through the GUI or `noctalia msg plugins source add` land in `settings.toml`, which would override the `host.toml` list. Drop the fork once the PR merges.

`lady-grey`'s `host.toml` disables idle screen-off, lock and suspend (`loft-idle` shows the photo frame instead) and drops the media, tray, volume, Bluetooth and power-profile entries (no audio). It adds a second bar, `bar.side`, on the left edge, at `thickness = 102` (3x the 34 px default): one `custom_button` per kiosk app, each running `niri msg action focus-workspace <name>` and stacked at the top in workspace order (`ws-home`, `ws-music`, `ws-radarr` with `radar`, `ws-sonarr` with `device-tv-old`, `ws-lidarr` with `vinyl`), then a 24 px spacer (`side-gap`) and a `terminal` button (`terminal-2`, runs `loft-terminal`). The noctalia `launcher` sits at the bottom with a `rocket` glyph (fuzzel needs typing; the launcher is set to an app grid that opens attached to the bar next to the button). `capsule_padding = 10` (default 6) makes the side-bar buttons taller. `bar.main` keeps `workspaces` and the rest at `thickness = 51` (1.5x).

Lid close: `blanco` locks only. `work` locks and suspends via noctalia, and `niri-lid-inhibitor.service` holds logind's lid-switch inhibitor while the graphical session is active so logind doesn't suspend first.

### blanco overlay

- **chromium-newwindow.** Links clicked in kitty opened in a Chromium window on another workspace. Wayland only lets a running app raise itself with an xdg-activation token; kitty strips `XDG_ACTIVATION_TOKEN` from children and `xdg-open`'s portal path sends none, so niri correctly ignores the raise. The workaround is a `--new-window` wrapper that `deploy.sh` registers as the default browser, so every app's links land on the active workspace. It is `NoDisplay=true` and claims only `http`, `https` and `text/html`. Trade-off: one new window per link.
- **music-assistant.** Launches the PWA in the Chromium flatpak. Chromium's own entry is `NoDisplay=true` and rewritten on manifest changes, so this tracked copy is the one fuzzel shows.
- **loft.** A fuzzel launcher per loft host (`kitty --title <host> fish -c <host>`).
- **dunst-mask.** Shadows the system D-Bus service file for dunst with `Exec=/bin/false`. dunst arrives as a dependency of `system-config-printer` and claims `org.freedesktop.Notifications` before noctalia is up, producing default blue toasts. Removing the package would remove the printer config tool, and `dunst.service` is `static`, so D-Bus activation is its only entry point. The first notification of a session is dropped if noctalia isn't up yet.

### lady-grey overlay

Firefox kiosk windows, one per named workspace (Homepage on `home`, Music Assistant on `music`, then Radarr, Sonarr and Lidarr), with the Pupshow photo frame over them when idle. Settings (`KIOSK_DASHBOARD_URL`, `KIOSK_PHOTO_URL`, `KIOSK_PHOTO_IDLE`, `KIOSK_SCREEN_OFF_IDLE`) come from `/etc/default/loft-kiosk`, written by the-loft from its `host.conf`. greetd and `loft-kiosk-session` (which restarts `niri-session` on exit) also stay in the-loft. Deploy as `rodnik`: `sudo -iu rodnik`, clone, `./scripts/deploy.sh`, then `systemctl --user enable noctalia.service`.

- **niri.** `local.kdl` sets `eDP-1` to scale 2 (2736x1824 at 12.3"), hides the cursor, binds the power button to `power-off-monitors` (niri holds logind's power-key inhibitor, so the bind replaces niri's default suspend and logind never powers off), declares the `home`, `music`, `radarr`, `sonarr`, `lidarr` and `terminal` workspaces (named, so they survive their app closing and keep their order), and starts `loft-app home https://homepage.loft.hsimah.com/` (Homepage, until Home Assistant on Capcom is ready), `loft-app music https://howlr.loft.hsimah.com/` (Music Assistant), `loft-app` for `radarr`, `sonarr` and `lidarr` at `https://<name>.loft.hsimah.com/`, and `loft-idle` with `spawn-sh-at-startup` so `~` expands. Firefox opens maximized under the bars; `open-fullscreen false` only catches a fullscreen request made while the window opens, so `loft-app` handles the later `--kiosk` one.
- **kiosk.** `loft-dashboard` waits for any HTTP answer from the dashboard (a failed first load leaves Firefox on an error page with no retry; Home Assistant answers 400 until `trusted_proxies` is set), then runs Firefox in a restart loop. `loft-idle` is swayidle: after `KIOSK_PHOTO_IDLE` seconds `loft-photo-frame start` opens a second Firefox on Pupshow and fullscreens it by PID over the dashboard and bar; the next input stops it. It does nothing while Pupshow's `/health` fails. `KIOSK_SCREEN_OFF_IDLE` > 0 also powers the panel off. `loft-app <workspace> <url>` is the per-workspace version of `loft-dashboard`: it waits for the URL, runs Firefox in a restart loop on its own profile, and after each launch moves the window (found by PID) to its workspace without stealing focus, then for 30 s switches it to niri's windowed fullscreen whenever its tile covers the whole output (at most 3 times). Firefox's `--kiosk` asks for fullscreen some time after the window opens (seconds later on a slow page), too late for the `open-fullscreen false` rule, so a fixed delay isn't enough; windowed fullscreen keeps kiosk mode's hidden toolbars while the window stays tiled under the bars. Adding an app is a `workspace` line, a `loft-app` startup line and a side-bar button. `loft-dashboard` (Capcom from `KIOSK_DASHBOARD_URL`) is no longer started; `home` runs Homepage through `loft-app` for now. `loft-terminal` (the side-bar terminal button) moves the `terminal` workspace to index 6 (a named workspace added by a config reload lands out of order), focuses it, and starts kitty only if no kitty window is already there. The Firefox profiles live in `~/.local/share/loft-{dashboard,photos,<workspace>}-firefox` and share one `user.js` (the others are symlinks to the dashboard one; `loft-app` creates its link on first run).

### work overlay

- **workplace, metamate, claude-code-work.** Fuzzel launchers with their own icons. Workplace and the Metamate spaces open as Chrome `--app=` windows; the Metamate launchers bypass the PWA because its `focus-existing` launch handler ignores the target URL. Claude Code @ Work opens `~/work` in kitty and runs `claude`.
- **od-connect** (`~/.local/bin`) prompts for a YubiKey touch, then runs `dev connect <args> -- <bootstrap>`. `dev connect` delivers PROG by *typing* `exec <PROG>; exit` into the remote shell, so the multi-line `od-tmux-boot.sh` is gzip+base64-encoded into one single-quote-free line. Anything after `--` skips the bootstrap and is passed through as PROG, one argv element each (`dev connect` quotes each individually, so a pre-quoted string arrives as one command name).
- **od-tmux-boot.sh** runs on a fresh OD. It waits in parallel for `dotfiles.target` (the dotsync pull) and `devfeature status` to report `Initial sync: successful`, because shells spawned earlier lack aliases. Then it creates tmux session `main` (one shell pane at `~`) or re-attaches. Two details matter: `default-command "exec bash -l"` makes panes login shells so aliases load, and `TERM=xterm-256color` is forced because the OD has no `xterm-kitty` terminfo. A tmux server with no sessions exits (tmux 3.7), so `start-server` followed by `set-option -g` can fail; it works on the OD's tmux today.
- **dev-connect-\*.** Fuzzel entry points that call `od-connect`: `-t www`, `-t www_fbsource_configerator:ent_framework`, and the devserver (`-n "$DEVSERVER_HOST"`, read from `.env`). The devserver is persistent, so it skips the bootstrap and runs `tmux new-session -A -D -s main` under `bash -lc` with `TERM` forced, falling back to a login shell.

## Autologin

`blanco` and `work` are display-manager-less: LUKS passphrase, agetty autologin, fish, niri. `lady-grey` uses greetd instead (the-loft).

[`scripts/setup-autologin.sh`](scripts/setup-autologin.sh) is the system side. It templates [`system/getty-autologin/autologin.conf`](system/getty-autologin/autologin.conf) into `/etc/systemd/system/getty@tty1.service.d/` and disables any display manager. `bootstrap.sh` runs it on `blanco`; run it by hand on `work` to leave GDM (rollback: `sudo systemctl enable gdm`).

The session side is `conf.d/autologin-niri.fish`, which `exec`s `niri-session` from the login shell on tty1 only, when not already inside niri (`NIRI_SOCKET`). Its `status is-interactive` check is load-bearing: `niri-session` re-execs itself through `$SHELL` as a login shell, and without the check the snippet fires again and the two exec each other forever.
